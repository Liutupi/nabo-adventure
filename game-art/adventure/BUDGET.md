## 3. 预算

以下是开发布局的整包规划，不代表旧布局设备可一次装下所有新游戏。字体/欢迎V2a候选的共用包实际RLE/表及C3结构体/目录估算见 `firmware/main/generated/adv_assets_generated.json`：travel167,547 B、static70,902 B、UI57,244 B。开机演员（含152B时间表）102,381 B另外与UI合计159,625 B，低于160KiB，未通过挪预算隐藏人物费用。编码器使用无损literal/最优关键帧和明确物理帧排序，原画面/曝光顺序/尺寸不变；链接对齐及最终镜像须另看ELF/app。当前候选app1,533,920 B，真实旧factory余497,696 B；SHA256见ART_PROGRESS/VALIDATION，尚待新候选真机。

| 用途 | 额度 | 说明 |
|---|---|---|
| 保留余量 | 352 KiB | 永远不分配：字库扩充、修复、将来的游戏 |
| 界面包 | 160 KiB | 封面插画、字标、九宫格、护照内页、数字、标签、地图界面元素（UI_DESIGN 7.8） |
| 共用包 + 地图 + 印章 + 图标 | 400 KiB | NABO 旅行服动作约 40 帧、9 组图块、9 个地标、9 枚印章 |
| 每个新游戏（6 个） | 素材 ≤ 260 KiB，代码 ≤ 40 KiB | 合计 ≤ 1.8 MiB |
| 结局 | 100 KiB | 主要用地图本身，不做大图 |
| **合计** | **≈ 2.8 MiB** | 与剩余 2.83 MiB 基本持平 |

如果超了，先压缩已有素材，再动新游戏：

1. 跳一跳精灵改成 64 色调色板 + 逐帧压缩：117 KB → 约 20 KB（整包 zlib 实测 19.5 KB）。
2. 跳一跳音效改成 ADPCM 或程序合成：243 KB → 约 60 KB 或 0。
3. 深潜沿用的两套字库（170 KB）和外壳字库合并成一套。

这三项能再空出约 0.5 MB。

## 4. 每个游戏的素材怎么算

按深潜实测：66 px 的 NABO 帧，64 色 + 逐帧压缩后平均 **1.16 KB/帧**。

| 内容 | 估算 |
|---|---|
| 第一款服装动作 30–40 帧 | 35–50 KiB |
| 第二款服装（移动循环 + 欢呼）约 14 帧 | 16 KiB |
| 结算欢呼 8 帧（72 px） | 12 KiB |
| 场景图块 + 道具 | 40–80 KiB |
| 音效（优先程序合成） | 0–20 KiB |
| **合计** | **约 100–180 KiB** |

260 KiB 的额度留了余量。整屏大图、视频式动画（牌桌那种 1.2 MB）不要用。

## 5. 运行内存

- 外壳打开时：显示列表 2 × 128 个操作 + 320 个字形 + 两条 320×8 的 DMA 条带（条带共10,240B，比竖屏版多2560B）；横屏旋转复用空闲条带，无整屏缓冲。
- 外壳游戏的状态由外壳 `calloc`，回地图释放。占位游戏只有几十字节；正式游戏建议 ≤ 16 KB。
- 深潜打开时约 45 KB（《游戏特辑》实测），跳一跳用外壳的条带。
- 真机上要用 `>adv.status` 记录：地图、每个游戏中、回地图后的 `heap` 和 `largest`，进出 10 轮不能下降。**v0.1.0 还没测。**
