## 1. 固件底座

- 从独立离线版《NABO 游戏特辑》v1.0.0（`Liutupi/nabo-games`）分出来，**去掉牌桌**，保留深潜和进阶跳一跳。
- 不启动 Wi-Fi、蓝牙、小智、麦克风。开机直接进合集封面。
- 分区表不变：app `0x10000`（0x3f0000），assets `0x400000`，files `0x700000`。所有素材嵌进 app，**不读写 assets 和 files 分区**，这样和其他 NABO 固件来回切换时互不影响。
- 设置和成绩沿用 NVS 命名空间 `nabo_ui`：音量、亮度、休眠、跳一跳和深潜的最佳成绩会从《游戏特辑》直接继承。

- **站点编号**就是解锁顺序：1 跳一跳 → 2 深潜 → 3 小火车 → … → 8 太空。
- **解锁**：护照亭和跳一跳一开始就开；站点 n（n ≥ 2）在站点 n−1 拿到铜章后解锁。
- **占位关卡**：POST站3现已接 `adv_post.c` 正式规则，门槛5/12/25；站4–8仍跑 `adv_demo.c`，门槛临时3/6/10。只有正式规则、渲染和验证一起落地才移除对应占位标记，不能只改显示文案。
- **类型**：旧游戏（跳一跳、深潜）自己画标题和结束画面，外壳只负责进出和读回最佳成绩；外壳游戏只实现“游戏中”，标题、倒计时、暂停、结算、资源条都由外壳统一做（第 5 节）。

### 2.1 在地图上走

- NABO 站在某个站点上（开机在跳一跳）。UP 沿路径往上一站，DOWN 往下一站。
- 可以**往前看一站**：走到第一个没解锁的站点上看它（显示“拿到 X 的铜章后解锁”），但不能越过它。规则：当前站和目标站至少一个已解锁，才允许移动；否则播“不行”的提示音。
- 镜头跟着 NABO，目前是直接跳到新位置（整屏重画）。平滑滚动要用 ST7789 硬件竖向滚动，见 HANDOFF 的待办。

## 3. 按键

按键事件和 BSP 一致：PRESS、RELEASE、CLICK（单击）、DOUBLE（双击）、LONG（长按 500 ms）。**所有游戏返回地图统一为双击上键**；游戏内单击、长按上键不会退出。菜单页仍保留长按上或双击上返回。

|---|---|---|---|---|---|

| 设置 | 沿用《游戏特辑》 | | | | 取消调整 / 回护照亭 |
| 盖章 | — | — | 收下这枚章 | — | — |

新游戏进行中上键保留玩法操作，长按上暂停；双击上从任何阶段直接回地图，含练习、倒数与结束动画。已结束但尚未到结算页时退出，先结算该局纪录，防止跳过结束动画丢掉成绩；进行中提前退出仍沿用原来的未完成局规则。练习与测试分数不保存。

## 4. 印章

- 每个游戏三枚：铜、银、金。最佳成绩 ≥ 门槛就算拿到。章只会增加。
- 编号：站点 s 的第 t 档（0 铜 1 银 2 金）是第 `(s − 1) × 3 + t` 位，共 24 位。
- **盖章仪式**：每次回到地图（从封面、游戏、护照亭、旧游戏回来）时，如果有拿到但还没展示过的章，就按编号从小到大一枚一枚展示，OK 收下。展示过的记在 `adv_seen`。
- 已收下的24位有效印章始终保留；占位玩法换正式规则、门槛上调时也不撤章或重锁后续入口。不增加虚构最好成绩，不改写已有NVS。高于24位的无效位不参与计章。
- 章的含义（文字已经显示，功能还没做）：铜章解锁下一站；银章解锁这个游戏的第二款服装；金章是护照金章，8 枚金章全拿到放结局。

## 5. 外壳游戏的一局

```
标题 ──OK──▶ 准备（3 秒倒数）──▶ 进行中 ──资源归零──▶ 结束（2 秒）──▶ 结算
  ▲                               │  ▲                                 │
  │                         长按上│  │OK                               │OK 再来一局
  │                               ▼  │                                 │
  └────────── 返回 ───────────── 暂停 ──下：重新开始──▶ 准备 ◀──────────┘
```

上图为一局内部流程；任意游戏阶段均可双击上键直接退出到地图，长按上不承担退出。

- 逻辑固定 60 Hz 步进（`adv_step`），和画面帧率无关。准备 180 步，结束 120 步。
- 每局开始时外壳用自己的 mulberry32 生成新种子交给游戏。同一种子 + 同一串按键 = 完全一样的一局。
- 进行中的按键沿（按下、松开）攒到下一步一起交给游戏；同时给出 OK、DOWN 当前是否按住。
- 结束时如果成绩超过最佳，结算页显示“新纪录”并保存（测试模式只显示“测试不记录”，不保存）。

## 6. 游戏接口（`firmware/main/adv_game.h`）

```c
typedef struct { uint8_t ok_down, ok_up, up_down, down_down, down_up, ok_held, down_held; } adv_input_t;
typedef struct { uint32_t score; int resource; bool over; uint8_t cue; } adv_status_t;
typedef struct {
    const char *id; size_t state_size;
    void (*start)(void *state, uint32_t seed);
    void (*step)(void *state, const adv_input_t *in);     // 固定 60 Hz
    adv_status_t (*status)(const void *state);
} adv_game_t;
```

- `resource` 0–1000，外壳画在顶部；低于 250 变红。撞到东西统一扣 250（四分之一）。
- `over` 置位后外壳进入结束阶段，继续调用 `step`（输入全空）2 秒，让游戏播完结束动作。
- `cue` 是本步要播的提示音（`adv_cue_t`），游戏自己的音效以后单独加 `audio_fill`。
- 状态内存由外壳在进站时 `calloc(state_size)`，回地图时释放。游戏不要自己 malloc。
- 画面：游戏另写一个 `draw(const void *state, ag_t *g)`，在 `adv_ui_session.c` 里按站点挂上（现在只有占位游戏的 `draw_demo`）。画面只能读状态，不能改。

## 8. 串口诊断（115200，行首 `>`）

| 命令 | 作用 |
|---|---|
| `>adv.status` | 页面、站点、阶段、成绩、资源、章、堆、最大连续块、上一帧发送字节、各站最佳 |
| `>adv.key=up\|down\|ok\|long_up\|double_up\|long_ok\|long_down` | 注入一次按键 |
| `>adv.edge=<键>,<0/1>` | 注入按下/松开沿（0 上 1 下 2 OK） |
| `>adv.capture` | 下一帧以 `@cap` 行输出 RGB565（深潜里不可用） |
| `>adv.test=1` | 测试模式：外壳、跳一跳、深潜成绩、深潜教程标记及设置均不写 NVS。脚本测试必须先打开 |
| `>adv.test=0` | 先停止测试游戏，再从 NVS 重载原设置和成绩回封面；测试过程中产生的临时成绩不会补存 |
| `>adv.open=jump\|dive` | 仅测试模式且停在地图时可用；直接走旧游戏的真实分配/退出链路，不依赖解锁，不改成绩或印章 |
