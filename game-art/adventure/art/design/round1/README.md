## 文件

- `sources/`：九张分别交付的 SVG；头部、服装、四肢、包和次级动画部件有独立 `id` / `data-part` 分组。同名 `-4x.png` 是本地 SVG 渲染的高分辨率中间稿。
- `characters/`：九张 **256×256 RGBA PNG**，脚底锚点固定为 **`(128,224)`**。
- `targets/`：九张透明 64×64 RGBA 目标尺寸预览，每张量化至不超过 64 个 RGBA 颜色。
- `previews/`：两个世界底色上完成 64 色量化与 RGB565 模拟后的 1× PNG。底色为小镇 `#F6E2B4`、深海 `#0B2A4A`。
- `palette.png`、`palette-and-qa.json`：源矢量调色板、画布、边界、颜色数、锚点与 PNG SHA256。
- `provenance.json`：沿用的原始头部文件 SHA256、三方向共用头部的分组 SHA256，以及渲染工具与字体说明。
- `visual-review.md`：本轮逐图检查记录和待用户决定的部分。

## 角色身份与左右方向

正面直接复制 `game-art/dive/rig/common/front/` 的头、眼镜眼睛和嘴部几何。左侧使用 `common/head.svg`、`eyes_neutral.svg` 和 `mouth_neutral.svg`。右侧仅对不含帽标的原始头部几何做投影，帽顶折线和 `NABO` 字样单独正向放置；字样沿用正面已有的字形路径，避免字体替换或反字。三个方案的同方向头部完全共用同一份几何，脚本会核对分组 SHA256。

左右视角分别生成 SVG，服装使用正比例投影并独立摆放包、包带和背包；没有整个人物镜像。原有深潜文件全部只读。轮廓沿用身份部件的深色描边，服装使用固有色的暗色描边；采用平涂与两阶阴影，没有白色贴纸边、光晕或软 3D 光照。

## 重现

使用 bundled Python（Pillow）执行本目录 `build_designs.py`。脚本调用本目录 `rasterize.cjs`，通过 bundled Node.js 的 `sharp/librsvg` 渲染 SVG，然后输出 PNG、设计板与 QA；工具默认路径写在这两个脚本顶部，可在迁移机器时调整。

SVG 的帽标已经是矢量路径，只有设计板说明文字使用 Windows 微软雅黑。没有调用图像生成模型。源矢量每方案少于 64 色；源 PNG 保留抗锯齿，最终游戏用的统一动画调色板、行 RLE、关键帧与差分帧仍属于后续精灵管线。这一目录只含第 1 轮静态候选，不建立正式 rig、动作或固件素材。
