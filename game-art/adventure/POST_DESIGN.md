# 小火车 POST · 正式玩法开发

依据GAMES第1节，嵌入当前独立合集，保留已验收字体/欢迎与原NABO身份；复用第6轮美术，不新增造型。用户已授权开始正式开发，先POST再依次推进其它五款。

## 规则与输入

- POST单独采用320×240横屏，工牌顺时针横拿、三键在下沿；其余页面与旧游戏仍为240×320。上下轨基线132/212，车体参考x110、送信车头x156。LCD板级方向不变，两条320×8 DMA条带软件旋转，新增条带内存2560B，无整屏缓冲、不镜像NABO。
- 右上指示牌直接写“下一站 上轨/下轨”和该按哪个键；预选正确、通过岔口已锁定、实际换轨中分别提示。左侧同时显示当前轨道与预选轨道。下一站轨道由最近的未完成站台与尚未通过的对应岔口推导，不能把预选当成已经换轨。
- 指示牌限制在y32–66，不能盖住从y66开始的上轨站台与信封。上下轨各三个前方位置逐像素比较完整车站/信封与独立生产精灵参照；不能以看得见部分站牌代替无遮挡检查。
- 固定60Hz、mulberry32、整数；世界位置以1/60像素存储，初速90px/s。
- 上/下键按下选择下一岔口的上/下轨；在岔口120px连接段入口锁定选择，按实际行驶速度跨完整连接段平滑换轨。前1.5秒显示选线提示，下一站所在轨道提前显示，避免站牌尚未入屏就必须盲选。煤和牲畜使用当前实际y与轨道的20px范围判断，而非尚未到达的目标轨。
- OK少于24步（约400ms）松开卸信，**按下时**记录站台、实际y所在轨道和队首颜色。送信中心是可见车头x156、窗口±32px；与换轨/碰撞的x110车体参考点分开。成功+1并移除队首，失误扣250；已接受的短按等待期间不会提前判漏送。站点驶过同样扣250，单站错误卸信后不再重复扣。
- OK连续按满24步鸣笛，松开不卸信。前方同轨牲畜受连续鸣笛36步（600ms）后离开；碰撞扣250。按暂停菜单不会积攒新按键边沿。
- 蒸汽初始1000，每秒自然耗20，鸣笛额外30；同轨煤堆+300，上限1000。归零结束，外壳负责结束/结算/成绩/印章。
- 初始3封红蓝黄信，送完前往车库补3–5封、速度+8%（整数四舍五入），上限200；第三批开始增加绿色，完成第三次补给后出现羊牛。
- 岔口每150–240步生成，60%配站；站牌进入屏幕时固定为当前队首颜色，防止提前排程造成无信可送。站点选择轨道随机。空车回库期间不扣无法送信的站。
- 最佳成绩=送达封数，铜/银/金5/12/25。保留其它五款占位标记，POST通过完整验证后才去掉本款占位。

## M0–M4

1. `prototype/adv_post.js`为规则标准；浏览器试玩、实际画面和调参先行。
2. 录制确定性轨迹再移植纯C，含点按/长按边界、错轨/错时、煤、车库、加速、牲畜、耗尽及随机轨迹；故意改坏规则确认测试能发现。
3. 用原尺寸车体/轮/司机/汽笛绳/前景组合，帧同步；H模式上半背景保持固定，仅重画底部轨道带和移动物体。先证明增量=全屏，再量设备帧率。
4. 接外壳暂停/重开/退出、5/12/25印章、测试隔离；新增测试直达POST不伪造成绩或永久解锁。每次以刷前最新真实存档为准；已实读到121/5888/4和6枚章，不能退回旧99分/3章备份。
5. app必须小于用户旧factory2,031,616B，只写0x10000；不改分区、不写6MB旧资源区。保留557607…已验收二进制，新候选另外冻结/测试。

本文件的起始规则允许根据M0实际试玩修订；先改JS、重录轨迹再改C，不把已写设计当成已完成游戏。
