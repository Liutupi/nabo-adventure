## 二、给 Codex 的优先级清单

### P0　用户认可 G1 后：SKY / CLIMB 移植（G4）

路线写在两份概念文档末尾，完全照 SKI/SPACE 已走通的流程。**用户没说“可以”之前不要开始**；用户若要调整，先改 JS 再出新 G1。容量：已批准的各 72 KiB 净新增足够（SKY 需两张 2/3 尺寸的气囊/吊篮小图；CLIMB 新图约为 0）。

### P1　共用界面统一（只改画面，不改规则；每项都要宿主截图 + 用户看图确认）

REDESIGN_V2 §2.1/§5 要求的界面，目前生产画面还没有全部做到：

1. **标题页模板**：一张主视觉 + 一句话 + 三个按键标签（◀ / ● / ▶ 各做什么）+ 最佳成绩与三枚章。现状：`night-title.png` 四行说明、`ski-title.png` 两行说明再加两行底栏、`title.png`（POST）文字块很密。G1 试玩页里的标题就是这个模板，可直接照做。
2. **结算页**：分数从 0 滚到最终值（约 40 帧），越过门槛时盖章动画，下方一行“距银章还差 N 分”，统计只留一行主信息 + 一行次要信息。现状（`night-result.png`、`ski-result.png`）是静态大数字 + 一长行统计，没有离下一枚章的距离，盖章只在地图页发生。
3. **横屏 HUD 顺序一致**：资源条左上、连击/倍率中上、分数右上。SKI 因雪崩占顶部而放底栏可以保留，但元素顺序与其他款相同；SPACE 底栏两条 10 px 标签小字需在实机上确认能读。
4. **受击反馈**：G1 里撞击时整屏偏移 2 px、8 帧，失误有短文字。固件可用视口偏移零成本实现；先核对现有 NIGHT/SKI/SPACE 是否已有，再统一。

建议做法：在 `adv_ui_session.c`（或新文件，≤400 行）抽出 `title_card()`、`result_card()`、`hud_landscape()` 三个共用函数，再逐款替换；改完重生字库、跑渲染测试，核对非目标截图像素不变后再提交。

### P2　流畅性（要真机数字，不能拿宿主当结论）

1. **SKI V2 帧率从未单独测过**（交接本只有 NIGHT 28.7–29.9、SPACE 28.1–28.8 的 draw 计数）。用测试模式 `>adv.profile` 测 SKI 三个短窗，低于 25 fps 先报告再优化，不擅自改玩法数值。
2. SKY V2 / CLIMB V2 都是整屏滚动：SKY 直接复用 SPACE 的 4 位云层索引缓存（同一批 `space-v2` 背景）；CLIMB 岩壁是 32×32 贴图纵向滚动，按行条带合成即可，夜晚光圈若贵就改按行压暗（借 NIGHT 的实现）。
3. 按键到画面回应 ≤1 帧（REDESIGN §2.6）目前没有自动检查；可在宿主 harness 里加一条：按键边沿当帧的显示列表必须与上一帧不同。

### P3　保持不变的东西（用户已拍板，别“顺手统一”）

竖屏旧游戏的手势（POST 长按上暂停、深潜单击上暂停、全部双击上回地图）、地图/护照/设置的菜单操作、静音设置、开机视频与口号、NABO 身份锁定规则，都维持 AGENTS.md 里的约定。
