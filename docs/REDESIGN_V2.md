# 第二版重做规划：萤火虫起五款游戏（V2）

2026-10-26 13:22 用户实玩 ddd1f50d 后的反馈，原话要点：

1. 从萤火虫开始游戏性大打折扣，甚至有点无聊，远不如第一款深潜。
2. 美术和 UI 不行，人物动作僵硬，像贴片人。
3. 要重新设计规划；对 Codex 要求高一点；涉及动作的东西放手交给 Grok。
4. 需要左右操作的游戏必须横屏，否则反人类。

本文件是 V2 的唯一规划入口。**在用户确认第 7 节的决定之前，Codex 不再继续打磨现有 NIGHT/CLIMB/SKI/SKY/SPACE 的 V1 玩法、动作或界面**；V1 保持可玩、可回退，不删除。

## 1. 诊断：为什么深潜好玩、后面几款不好玩

### 深潜做对了什么（V2 的标尺）

| 要素 | 深潜的做法 |
|---|---|
| 持续操控 | 人物一直在动，每 0.3–1 秒就有一次“变向还是不变”的决定 |
| 风险与收益 | 气泡在障碍旁边，贪气泡就要贴近危险；俯冲更快更深也更难躲 |
| 节奏升级 | 越深越快、越密、越暗，局长自然收敛在一两分钟 |
| 擦身而过 | 障碍密度让“差一点撞上”频繁发生，紧张感来自这里 |
| 反馈 | 俯冲压陡 15°、拉长 10%、速度线、气泡尾迹、呛水动作，全都即时 |
| 角色 | 姿态和朝向一直随操作变化，缺氧/呛水有专门表演，不是一张图平移 |

### V1 各款的问题（诚实评估）

| 游戏 | 核心问题 |
|---|---|
| NIGHT 萤火虫 | 本质是“等光点亮 → 走过去 → 按键”。没有连续操控，没有风险选择，等待时间多于决策时间 |
| CLIMB 登山 | 回合制：每次动作锁 0.4–0.5 秒，玩家多数时间在看动画；竖屏下没有空间感 |
| SKI 滑雪 | 竖屏左右转向反人类；障碍稀疏，旗门判定单一，没有技巧和连击 |
| SKY 热气球 | 单键 Flappy；气球占半屏，几乎没有躲避空间；高度决策没有意义 |
| SPACE 太空 | 每轮只是一次慢慢下降；不能倾斜，侧推手感生硬；轮与轮之间没有变化 |

共同问题：玩法是“规则正确”，不是“好玩”。V1 的验收标准是宿主对拍和平衡数字，这能证明没有 bug，证明不了乐趣。

### 美术与 UI 的问题

- **动作僵硬的根源**：人物动作来自 SVG 部件骨骼——头、前臂、手作为硬片旋转，没有预备、跟随、重心转移和衣物次级运动；每个动作 4–8 帧、12fps，循环短。这就是“贴片人”。
- 背景大多是纯色或一层平铺，没有层次和空间深度；没有粒子、闪光、屏幕震动等反馈。
- 标题页是成段文字说明；结算页是通用弹窗；各款 HUD 风格不统一，信息层级弱。

## 2. V2 设计原则（每款都必须满足，Codex 自查后交用户）

1. **一句话可玩**：标题页只有一句话 + 三个按键图标，3 秒内看懂；不再写段落。
2. **持续操控**：进行中每 0.5–1 秒至少有一个有意义的决定；不允许“等动画播完才能操作”超过 0.3 秒。
3. **风险换收益**：至少一种“贪了更多分但更危险”的选择（贴近障碍的奖励、连击倍率、高分区）。
4. **擦身而过**：设计和调参要让“差一点”频繁出现；用宿主模拟统计“险过”次数。
5. **节奏升级与事件**：每 20–30 秒有一次变化（新障碍、天气、Boss/特殊波次），一局 60–150 秒。
6. **即时反馈**：按键 1 帧内有画面回应；命中、失误、连击都有粒子/闪光/震动/音效（音效在静音设置下不播放）。
7. **角色会演**：NABO 的姿态随操作连续变化；成功、失误、险过、低资源都有专门表演。
8. **小屏可读**：在实际 320×240 / 240×320、实际配色上一眼分清角色、危险、奖励。

## 3. 横竖屏与按键（V2 统一方案）

### 方向

| 游戏 | V2 方向 | 理由 |
|---|---|---|
| POST 小火车 | 横屏（已是） | 不在本轮重做范围 |
| NIGHT 萤火虫 | 横屏（已是） | 左右移动 |
| CLIMB 登山 | **横屏** | 左右手交替抓握，左键=左手、右键=右手 |
| SKI 滑雪 | **横屏** | 侧视速降，前进方向就是屏幕右方 |
| SKY 热气球 | **横屏** | 水平飞行要看到前方，气球缩小 |
| SPACE 太空 | **横屏** | 左右旋转/平移 + 中键主引擎 |
| 地图、护照、菜单、跳一跳、深潜 | 竖屏不变 | |

### 横屏键位（顺时针横拿，三键朝下，与 NIGHT 一致）

| 物理位置 | 键名 | V2 语义 |
|---|---|---|
| 左 | OK | 左 / 左手 / 左转 |
| 中 | DOWN | 主要动作（举罐、跳、加热、主引擎） |
| 右 | UP | 右 / 右手 / 右转 |

### 返回与暂停（**需要用户拍板**，见第 7 节）

V2 里右键（UP）会被频繁点按（例如 CLIMB 的右手），“双击上键回地图”在进行中必然误触。建议：

- **横屏游戏进行中：长按中键暂停**；暂停页里双击上键回地图、中键继续、左键重来。
- 标题、结算、暂停页：双击上键照旧回地图。
- 竖屏页面与旧游戏不变。

## 4. 五款游戏的 V2 概念

每款给出核心循环、键位、风险收益、节奏事件和所需动作。数值在浏览器原型里定，不在这里拍脑袋。

### 4.1 NIGHT V2「萤火虫之夜」

- **核心循环**：横版小路，NABO 持续向右走，左右键控制走快/走慢（甚至后退一步），中键挥罐。萤火虫成群沿曲线飞过（不是原地闪一下），挥罐时机和站位决定一网抓几只。
- **资源 = 光**：罐子的亮度就是精神/资源，会慢慢变暗；**光照范围真实影响可见范围**，越暗越看不清路上的树根和水坑（绊倒扣光）。
- **风险收益**：同色连抓叠倍率；金色萤火虫只在飞蛾群旁边出现；罐子攒满可以按中键长按“放光”，照亮一段路并把附近萤火虫全吸过来（大招）。
- **节奏事件**：萤火虫潮、起风（虫群改变轨迹）、猫头鹰俯冲（需要躲）。
- **动作（Grok）**：走路/小跑循环、挥罐（前/上/后三种）、抓到满足、绊倒、被猫头鹰惊吓、放光大招、打哈欠（低光）、结算欢呼。

### 4.2 CLIMB V2「交替攀岩」

- **核心循环**：横屏，岩壁纵向滚动。左键=伸左手、右键=伸右手，必须左右交替抓到对应一侧的岩点才能上升；节奏越快爬得越快，抓空或同侧连按会打滑。
- **决策**：岩点在左右两侧不规则出现，有时要“跨一大步”（长按中键蓄力跳）；结冰岩点要按住才抓牢，碎石要快速离开。
- **风险收益**：快速连续交替有速度加成和“节奏连击”；水壶和登山旗在难走的路线上。
- **节奏事件**：落石（屏幕边缘提前预警）、阵风把身体吹偏、雪崩冲刺段。
- **动作（Grok）**：左手/右手各自伸出抓握（交替时身体重心左右摆）、蓄力下蹲、跳跃、打滑、悬空单手吊、被落石擦过、登顶插旗。

### 4.3 SKI V2「雪坡速降」

- **核心循环**：横屏侧视，地形是起伏的雪坡，NABO 从左向右自动滑行（参考 Alto's Adventure）。中键起跳（按住更高），空中左键后空翻、右键抓板做技巧，落地角度对了加速，不对摔倒。
- **风险收益**：技巧越多倍率越高，但落地前没完成就摔；岩石、断崖、雪堆、彩旗门（穿过加分）。
- **资源**：体温随时间下降，技巧和热可可小屋回温。
- **节奏事件**：日落/夜滑（光线变化）、暴风雪（可见距离缩短）、追逐的雪人。
- **动作（Grok，侧视）**：滑行循环、压低加速、起跳、后空翻、抓板、完美落地、摔倒翻滚、爬起、结算。

### 4.4 SKY V2「风层热气球」

- **核心循环**：横屏，气球缩小到约 1/3 屏高，世界向左滚动。中键加热上升，左键放气快速下降，右键向下方投递邮件。
- **决策**：不同高度有不同方向和速度的风层（用飘动的云带表示），选对风层才能追上浮空岛投递点。
- **风险收益**：投中靶心加倍；低空风快但有树和鸟，高空稳但有雷云（闪电先预警再劈）。
- **节奏事件**：雷暴、彩虹加分段、候鸟迁徙。
- **动作（Grok）**：拉绳加热、拉放气阀、投递（俯身扔出）、被颠簸、接邮票欢呼。气囊/吊篮是机械件，可由 Codex 程序化做摆动和挤压。

### 4.5 SPACE V2「月面着陆」

- **核心循环**：横屏，真正的 Lunar Lander：左右键旋转着陆器，中键主引擎。地形起伏，有多个着陆台，**越小越难的台子倍率越高**。
- **资源**：燃料；平稳着陆后可选择“加油继续”（下一关）或“冲刺高倍率台”。
- **节奏事件**：陨石雨、低重力关、需要把货物运到基地的任务关。
- **美术**：着陆器是机械件，Codex 可以从高清源图离线渲染 16 个旋转角度（只旋转整体，不做角色骨骼），NABO 在头盔里的表情另由 Grok 做小段循环。
- **动作（Grok）**：舱内紧张握杆、喷射时的反应、着陆松一口气、硬着陆被震、出舱插旗跳一下、结算。

## 5. 美术、动作与 UI 的 V2 要求

### 动作分工（用户 2026-10-26 明确授权）

- **NABO 的所有角色动作一律交给 Grok**（图生视频 → Codex 抠像、固定锚点、抽帧、限色、打包）。Codex 不再用 SVG 部件骨骼旋转做角色表演，也不要“先自己试几轮再说”。
- Codex 负责：为每个动作准备身份锁定的起始图和明确任务书（格式沿用 `grok-handoff/boot-v3/README.md`）、检查交回原片、后期处理与容量。
- 道具、背景、机械件（气球、着陆器、轨道、岩壁）由 Codex 做；需要有机运动的（萤火虫群、鸟群翻飞）可以程序化或另交 Grok。
- 帧数标准：核心循环 ≥8 帧、单次动作 8–16 帧、12–15fps；必须有预备、跟随和收势；首尾帧能接回循环。小屏实看清楚脸和帽标。
- 任务清单见 `game-art/adventure/art/grok-handoff/V2-ACTIONS.md`。

### UI

- 横屏统一 HUD：左上资源条（图标 + 条），右上分数，中上连击/倍率，底部不再常驻文字提示。
- 标题页：一张游戏主视觉 + 一句话玩法 + 三个按键图标（左/中/右各做什么）+ 最佳成绩与三枚章。
- 结算页：NABO 专门的结算表演、分数滚动、新纪录/盖章动画，而不是通用弹窗。
- 背景至少两层视差；关键反馈（命中、失误、连击）有粒子/闪光/震动。
- 先在 Design 里出界面稿给用户选，选定后才写 C。

## 6. 对 Codex 的工作要求（V2 质量门）

每款按顺序过门，**上一道门没有用户明确认可，不进入下一道**。宿主测试通过只代表没坏，不代表好玩。

| 门 | 交付 | 通过标准 |
|---|---|---|
| G0 概念 | 一页概念（核心循环、键位、风险收益、事件、动作清单）+ 30 秒流程示意 | 用户认可方向 |
| G1 可玩原型 | 浏览器横屏原型，键位与工牌一致（← ↓ → 或 A S D），占位美术即可 | 用户亲手玩，认为“好玩、想再来一局” |
| G2 动作 | Grok 任务书 → 原片 → Codex 抽帧后的 GIF/接触表，按实际尺寸和背景 | 用户认可动作自然，不僵硬 |
| G3 界面 | 标题/游戏中/暂停/结算的界面稿 | 用户选定 |
| G4 固件 | C 规则对拍、生产画面、容量、真机 10 轮 | 用户实机试玩认可 |

另外的硬性要求：

- 原型阶段就要统计：每分钟决策次数、险过次数、死因分布、一局时长；数字附在 G1 交付里。
- 不能把“规则对拍通过、平衡数字好看”当成好玩；不能把宿主截图当成实机观感。
- 不准用成段文字教学；不准把同一张人物图平移当动作。
- 交付时写清楚：做了什么、没做什么、哪些需要用户亲手验证。
